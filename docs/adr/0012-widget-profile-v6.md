# ADR-0012: ウィジェットのドキュメントは WIDGETS_V6 で書き、シェーダーを使わない

- ステータス: 採択
- 日付: 2026-10-04
- 関連: ADR-0009, ADR-0010, docs/spikes/README.md（⑤ 結果・② 結果・「WIDGETS_V6 と WIDGETS_V7 の違い」）

## 背景

ホーム画面のウィジェットは、ランチャーの中の OS 内蔵プレイヤーが再生する。作成側は、プロファイルで「どのプレイヤー向けの命令セットで書くか」を選ぶ。ウィジェット用には `WIDGETS_V6`（API レベル 6、Android 16 向け）と `WIDGETS_V7`（API レベル 7、プロファイル方式）がある。

スパイク②⑤で次のことがわかった（Pixel 6a、内蔵プレイヤーは API レベル 8）。

- 両方とも表示・時刻の式・開花の補間・ドキュメント内のタップが動き、放置中も 60fps で描かれた
- `WIDGETS_V7` はシェーダー（`DATA_SHADER`）を書けない。`WIDGETS_V6` は書けるが、内蔵プレイヤーが既定でシェーダーを拒否するので単色になる
- 今のドキュメントの式は、V6 の演算子の制限（API レベル 6 の範囲）に収まっている

## 検討した選択肢

1. **WIDGETS_V6** — API レベル 6 以上の内蔵プレイヤーで再生でき、対応する端末が最も広い。V7 で増えた命令（`PATH_EXPRESSION`、`COLOR_THEME`、`SMOOTH_STEP` などの演算子）とカスタムフォントは使えない
2. **WIDGETS_V7** — 命令が多く、これからの方式（プロファイル）に沿う。内蔵プレイヤーが API レベル 7 以上の端末でしか再生できない

## 決定

選択肢1。ウィジェットのドキュメントは `WIDGETS_V6` で書く。シェーダーは使わず、paint の色だけで見た目が成り立つようにする。

## 理由

- 手元の端末ではどちらも同じように動き、今のドキュメントは V6 の範囲に収まっているので、V6 を選んで失うものが今はない
- V6 なら、内蔵プレイヤーが API レベル 6 のままの Android 16 端末でも再生できる可能性がある（どの端末がどのレベルかは未調査）
- シェーダーはどちらのプロファイルでもウィジェットでは動かない（V7 は書けず、V6 は外される）。プロファイルの選択とは別に、使わないと決めておく

## 影響

- コンパイラは `DocumentTarget.WIDGET_V6` を使う。V6 用の Writer が式の演算子を書き込み時に検証するので、V6 で使えない演算子を使うと例外で気づける
- 空のグラデーションなど、シェーダーで作る表現はアプリ内（`DocumentTarget.IN_APP`）だけのものになる
- 見直しの条件: V7 にしかない命令（ダークモードのテーマ色、パスの式など）が必要になったとき。そのときは新しい ADR で V7 に切り替え、対応する端末が狭まることを記録する
