# ADR-0011: アルバムの正は成長データとし、.rc はライブラリ更新時に作り直す

- ステータス: 採択
- 日付: 2026-10-04
- 関連: ADR-0003（alpha の追従は意識的なタスク）, ADR-0010, docs/spikes/README.md（④ 結果）, docs/maintenance/library-upgrade.md

## 背景

成長アルバムは日ごとのドキュメント（.rc）を保存して再生する。Remote Compose は alpha で、新しい版のプレイヤーが古い版の .rc を読める保証がない。未知の命令が1つでもあると読込に失敗するため（スパイク④）、ライブラリを更新するとそれまでのアルバムがまとめて開けなくなりうる。

## 検討した選択肢

1. **.rc のバイナリを旧形式から新形式へ変換する機能をアプリに持つ** — 当時の見た目をそのまま残せる。ただし次の問題がある
   - 古い .rc を正しく読めるのは古い版のライブラリだが、同じパッケージの新旧2つの版を1つのアプリに同居させるには shading などが必要になる
   - alpha では命令の番号だけでなく引数や評価の仕方も変わりうる。正しく変換するには、実質的にプレイヤーをもう1つ書くことになる
   - androidx のプレイヤーは古いメジャーバージョンのドキュメントを読む前提で作られている。壊れるのは命令の削除や番号の変更が起きたときで、そういう変更ほど機械的な変換が効きにくい
2. **成長データ（Sim の状態）を正とし、.rc はそこから作り直せるキャッシュとして扱う**

## 決定

選択肢2。

- アルバムの各日には、`.rc` と一緒に次を保存する
  - 生成元の Sim 状態
  - 生成メタデータ: Remote Compose の版、Compiler の版（自前で採番する整数）、プロファイル
- ライブラリや Compiler の版が上がったら、メタデータの版が古い日を今の Compiler で作り直す（マイグレーション）。読込に失敗した日も同じ経路で作り直す
- 作り直す前の `.rc` は、必要ならアーカイブとして残せるようにする（必須にはしない）

## 理由

- 変換の正しさを保証する必要がなく、作り直しは Compiler を呼ぶだけで済む
- Sim と Surface をドキュメントで分ける構成（ADR-0002）の自然な帰結になる。正のデータは Sim 側にあり、ドキュメントはそこから作る出力にすぎない
- Phase 2（サーバー側生成）や Phase 3（種の共有）でも、成長データから作り直せる性質がそのまま役に立つ

## 影響

- 作り直した日は「今の描き方」で描かれる。当時の見た目を一画素まで残すことはできない。この作品では、育ち方（成長データ）が正しく残ることを優先し、絵柄の改良が過去の日に反映されるのは許容する
- Sim 状態のシリアライズ形式は、Remote Compose より長く読める必要がある。形式の版も一緒に保存し、変えるときはマイグレーションを書く
- Compiler の版は、描き方を変えたときに手で上げる運用になる
- 実装は `:core:data` を切り出すタイミングで行う。ライブラリ更新時の手順は `docs/maintenance/library-upgrade.md` にまとめる
