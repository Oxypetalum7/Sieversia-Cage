# ADR-0021: 毎日の成長 tick は 0 時過ぎに動かし、土が乾いた日だけ夕方に水やりを知らせる

- ステータス: 採択
- 日付: 2026-10-29
- 関連: ADR-0011（アルバムの作り直し）, ADR-0014（水やりの反応と記録）, ADR-0016（モジュール構成）, ADR-0019（M2 の計画）, ADR-0020（Sim と入力の記録）

## 背景

M2-4 で、Sim は植えた日から水やりの記録を当てはめて今日の状態を求められるようになった（ADR-0020）。ただし、ウィジェットとショーケースの絵は、まだ「今日まで毎日水をやった」前提のプレビューのままで、アルバムにはショーケースの日送りで作ったプレビューの日が記録されている。

発注書は「WorkManager で 1 日 1 回、Sim 更新 → ドキュメント再生成 → ウィジェット更新」を求めている。ADR-0020 では、土が乾いたときの水やりの通知を候補として書き、毎日の tick を作るときに決めることにした。

遊び方として、次のことを決めた（2026-10-29、ユーザーと相談）。

- tick は毎日 0 時過ぎに動かし、朝には新しい日の姿になっているようにする
- ショーケースは今日の本物の株を見せる。日送りは「先の姿のプレビュー」として残し、アルバムには書かない。今のアルバム（プレビューの日）は消す
- 通知は、土が乾いた日だけ夕方に 1 回知らせる。毎日は鳴らさない
- 水やりのタップを記録したら、ウィジェットを更新して「今日は水やり済み」を出す

## 検討した選択肢

### tick の動かし方

1. **WorkManager の定期実行（24 時間ごと）** — 作りは単純。動く時刻が決まらず、日付が変わってから半日ほど前の日の姿のままのことがある
2. **次の 0 時過ぎに一回きりの仕事を予約し、終わったら翌日の分を予約し直す** — 日付が変わってすぐに新しい姿になる。Doze で少し遅れることはある

### 通知

1. **入れない** — 土が乾く見た目（M3）だけで知らせる
2. **毎日決まった時刻に、その日まだ水をやっていなければ知らせる** — 忘れにくいが、鳴る日が多い
3. **土が乾いた日だけ、夕方に 1 回知らせる** — 鳴る日は少なく、知らせる理由がはっきりしている

## 決定

### tick: 0 時過ぎに一回きりの仕事を予約する（選択肢2）

- WorkManager の一回きりの仕事（一意の名前を付ける）を、端末の現地時刻で次の 0 時 5 分に予約する。終わったら翌日の分を予約し直す
- アプリの起動時にも、予約がなければ入れる。WorkManager の予約は端末を再起動しても残る
- tick の中身は次の 3 つ。PC でテストできるクラスに書き、Worker はそれを呼ぶだけにする
  1. **抜けている日を進める**: アルバムに記録した最後の日の翌日から今日まで、1 日ずつ状態を求める（`GrowthRepository.stateOn`）
  2. **アルバムに記録する**: 求めた日ごとの状態を、1 日 1 件記録する。tick が遅れたり抜けたりした日も、ここでまとめて埋める
  3. **ウィジェットを更新する**: 今日の本物の状態でドキュメントを作り、すべてのウィジェットに送る
- tick が遅れても困らないよう、同じ「抜けている日を進める」をアプリの起動時とウィジェットの `onUpdate` でも行う

### アルバムとショーケース

- アルバムは、本物の成長だけを記録する。植えた日を初めて決めたとき、それより前からあるアルバムの記録（今のプレビューの日）を消す（「植える前の記録はない」）
- ショーケースは今日の本物の株を見せる。「前の日 / 次の日」は先の姿のプレビューとして残し、アルバムには書かない（「今日まで毎日水をやった」前提で描く）

### ウィジェット

- `onUpdate` でも、今日の本物の状態を描く
- 状態の欄に「今日の水やり: 済み / まだ」を出す。これは Sim の出力ではない（その日の水やりが株に効くのは翌日、ADR-0020）ので、表示用の情報として Compiler に別に渡す
- **土の見た目は、その日の水やりをすぐ反映する**。Sim の土の湿り気は昨日までの記録で決まるので、そのまま描くと、水をやっても翌日まで乾いたまま見える。その日に水をやっていれば、同じ表示用の情報を使って湿り気を 1 として描く。成長が翌日から効くこと（ADR-0020）と、Sim の状態そのものは変えない（土が乾いていく見た目は M3 で作り込む）
- 水やりのタップを記録したら（ウィジェットでもアプリ内でも）、ウィジェットを作り直す
- ウィジェットを作り直す窓口は interface として `:core:data` に置き、`:feature:widget` で実装して Hilt でつなぐ（feature 同士は依存しない、ADR-0016）

### 通知: 土が乾いた日だけ、夕方に 1 回（選択肢3）

- 毎日 18 時（端末の現地時刻）に、tick と同じ方法で一回きりの仕事を予約する
- その日の土の湿り気がしきい値（0.5）を下回り、かつその日まだ水をやっていなければ、1 回だけ知らせる。2 日続けて水をやらなかった日の夕方に当たる
- 通知を押すとアプリが開く。通知のチャンネルは「水やり」の 1 つ
- **許可**（`POST_NOTIFICATIONS`、Android 13 以降）は、ウィジェットからは尋ねられないので、アプリの中で尋ねる。初めて水をやったあと、ショーケースに「土が乾いたら知らせますか？」という案内を出し、そこから許可を求める。断られたら案内は出さない

## 理由

- **0 時過ぎの予約**: 「毎日少しずつ姿が変わる」が体験の核なので、日付が変わったら早く新しい姿にしたい。tick が遅れても、抜けている日を後からまとめて進める仕組み（ADR-0020）があるので、時刻がずれても記録は欠けない
- **アルバムは本物だけ**: プレビューの日と本物の日が混ざると、アルバムの意味が崩れる
- **今日は水やり済み**: 跳ねる反応は一瞬で消えるので、記録されたことがあとから見て分かるようにする。土の見た目もすぐ湿らせ、「水をやったのに乾いて見える」を避ける
- **通知は水をやった日には鳴らない**: 条件に「その日まだ水をやっていない」を入れ、水をやったあとに知らせることがないようにする
- **土が乾いた日だけ**: 毎日鳴る通知は切られやすい。鳴る理由がはっきりしていて、鳴る日が少ない方が「気にかける」体験に合う
- **許可は理由が伝わるときに**: 初めて水をやったあとなら、何のための通知かが伝わる

## 影響

- 依存が増える: `androidx.work:work-runtime-ktx`（カタログにあり、2.12.0）と `androidx.hilt:hilt-work`（1.4.0）。Hilt で Worker を作るため、アプリの WorkManager の初期化を差し替える
- Compiler に表示用の情報（今日の水やり）を渡す口が増える。状態の欄の「水やり 3 回」（仮の値）はこれに置き換わる
- 通知の許可、チャンネル、ショーケースの案内の画面が増える
- 実機で確かめにくいもの（0 時・18 時の動き）は、WorkManager の予約を早めて確かめる。予約の時刻の計算は PC のテストで確かめる
- 日付や時刻帯の変更（タイムゾーンの移動など）は、次の起動時か tick で予約し直されるまでずれる。MVP では許容する
