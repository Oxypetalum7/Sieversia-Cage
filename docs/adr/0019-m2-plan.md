# ADR-0019: M2 は不明点の検証から始め、電池の確認とアルバムの保存形式の判断を加える

- ステータス: 採択
- 日付: 2026-10-29
- 関連: ADR-0012（ウィジェットは WIDGETS_V6）, ADR-0013（M1〜M4 の進め方）, ADR-0014（水やりの反応と記録）, ADR-0018（アルバムの正のデータは Room 3）, docs/spikes/README.md（② の「電池への配慮」）

## 背景

M1（骨組み）が終わった。ADR-0013 の M1 の項目はすべて片づいた。

- feature の切り出し（ADR-0016）
- `:core:data`（Room 3 に正のデータ、`.rc` の作り直し。ADR-0018）
- DI（ADR-0015 で Koin から Hilt に変更）、MVI、detekt の CI ゲート（GitHub Actions）

ADR-0013 は「各段階の終わりに、次の段階の計画を見直す」としている。M2 の元の項目は次の 4 つ。

1. Sim の本実装（経過日数・水やり・季節係数 → 枝ぶりと花の状態）
2. 毎日の成長 tick（WorkManager）
3. 水やりを Sim に届ける経路（ADR-0014）
4. 三段リフローとウィジェットでの文字表示の確認（ADR-0012 を見直すかの判断）

M1 の間に、M2 で扱うべきことが新たに 3 つ出てきた。

- **電池の確認**: ウィジェットは誰も見ていなくても 60fps で描き直し続ける。スパイク記録の「電池への配慮」で「M2 で確かめ、M3 で決める」とした
- **スパイク②で確かめていないこと**: 4x2 / 4x4 へのリサイズ、ランチャーを離れて戻ったときや画面のオン・オフの前後でアニメーションが続くか、ウィジェットのタップをアプリに届けるホストアクション
- **アルバムに何を保存するか**: ADR-0018 では Sim の出力だけを保存する。M2 で出力に項目を足すと、それより前に記録した日はマイグレーションで決めた仮の値で描かれ、新しい表現は過去の日に届かない。M1 の時点では Sim の入力は経過日数（主キー）だけなので、まだ何も失っていない。水やりや季節が入力に加わる M2 で決める必要がある

## 検討した選択肢

1. **ADR-0013 の項目の順のまま進める**（Sim → tick → 水やり → リフロー）— 作るものが順に積み上がる。ただし、採択済みの ADR を覆しうる不明点（ADR-0014・ADR-0012）が後ろに残り、覆ったときに Sim や tick を作り直すおそれがある
2. **覆しうる不明点の検証を先に行い、その結果をもとに作る** — 検証の段階では手応えが出にくいが、作り直しのおそれが小さい

## 決定

選択肢2。M2 を次の順で進める。

| 順 | 内容 | 種類 | 結果しだいで |
| --- | --- | --- | --- |
| 1 | 水やりの経路の検証（ドキュメント内の反応と、ホストへのアクションを同じタップで出せるか）。ウィジェットのタップもここで確かめる | 検証 | ADR-0014 を見直す |
| 2 | 三段リフロー（2x2 / 4x2 / 4x4）とウィジェットでの文字表示の確認。リサイズの見え方もここで確かめる | 検証 | ADR-0012 を見直す |
| 3 | 電池の確認（画面を消したときやランチャーを離れたときに描き直しが止まるか、`DOC_DESIRED_FPS` が効くか、`dumpsys batterystats` での消費の比較）。アニメーションが続くかもここで確かめる | 検証 | 対策は M3 で決める |
| 4 | Sim の本実装。アルバムに Sim の出力だけを保存するか、入力も残すかを ADR で決める | 実装 | ADR-0018 を補う |
| 5 | 毎日の成長 tick（WorkManager）。アルバムへの記録とウィジェットの更新 | 実装 | |
| 6 | 端から端まで通して確かめる（tick → Sim → アルバム → ウィジェット、水やり → Sim） | 確認 | |

- 1〜3 は「確かめて、判断を記録する」作業。結果はスパイク記録（`docs/spikes/README.md`）に残し、採択済みの ADR を覆すときは新しい ADR を起こす
- 4〜6 は、1〜3 の結果をもとに作る作業

## 理由

- ADR-0013 が選んだ「細い一本を先に通す」の考え方（不明点を早くつぶし、作り込みを無駄にしない）を、M2 の中の順番にも当てはめる
- 1 と 2 は採択済みの ADR を覆しうる。覆ったときに影響を受けるのは 4・5 の作り方なので、その前に確かめる
- 3 は 2 と同じウィジェットの作業で、実機の同じ準備で確かめられる。対策そのもの（フレームレートを下げる、夜は静止版に差し替える）は見た目と一緒に決めたいので M3 に残す
- アルバムの保存形式は、Sim の入力と出力の形が決まる 4 で決めるのが一番安い。公開前でデータは開発用だけなので、ここで変えても困る人がいない

## 影響

- M2 の前半（1〜3）は、画面に見える成果が少ない。各検証の結果はスパイク記録にまとめ、判断の根拠を残す
- 1〜3 の結果によっては、4〜6 の内容や順番を見直す。そのときはこの ADR を廃止せず、新しい ADR に見直しを書く
- M2 の終わりにも、M3 の計画を見直す（ADR-0013）
