# ADR-0001: 設計判断をADRで記録する

- ステータス: 採択
- 日付: 2026-10-03
- 関連: 発注書「目的とポートフォリオ戦略」

## 背景

本作は就活ポートフォリオであり、面接で技術談義の材料になることが目的の一つ。また Remote Compose はすべて alpha で、API変更への追従や退路の発動など「なぜその判断をしたか」が後から重要になる。技術記事の執筆時にも判断の経緯が素材になる。

## 検討した選択肢

1. **ADRとしてリポジトリ内にMarkdownで残す** — コードと同じ履歴で管理でき、GitHub上でそのまま読める
2. **コミットメッセージ・PR説明のみ** — 追加の手間はないが、判断単位で横断的に読み返しにくい
3. **外部ドキュメント（Notion等）** — 編集は楽だがリポジトリと乖離しやすく、ポートフォリオ閲覧者に届かない

## 決定

選択肢1。`docs/adr/` に1判断1ファイルで記録する。提案段階のものも `提案` ステータスで残す。

## 理由

- 判断の経緯がリポジトリを見る面接官・読者に直接届く
- alpha依存の追従や退路発動の際、前提を確認してから覆せる
- 技術記事の下書き素材として再利用できる

## 影響

- 設計上の提案・採択のたびにADRを追加する運用コストが発生する
- 覆す場合は新ADRを起こすため、判断の変遷がそのまま残る
