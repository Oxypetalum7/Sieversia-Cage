# ADR-0013: 本実装は「細い一本を先に通す」順で、M1〜M4 に分けて進める

- ステータス: 採択
- 日付: 2026-10-04
- 関連: docs/brief.md（開発発注書。ローカルにだけ置き、リポジトリには含めない）の MVP機能要件・フェーズ計画, ADR-0004, ADR-0005, ADR-0011, ADR-0012, docs/spikes/README.md

## 背景

初日スパイク ①〜⑤ がすべて実機で通り、構想の背骨（Sim → Compiler → ドキュメント → Surface）が成立することがわかった。本実装をどの順で進めるかを決める。期限は特になく、できるだけ早く Phase 1（MVP）を完成させたい。

スパイクの時点で残っている不明点は次のとおり。

- 水やりを Sim に届ける経路（ドキュメント内の反応とホストへのアクションを同時に出せるか）
- 毎日の成長 tick（WorkManager）でウィジェットを更新する流れ
- 2x2 / 4x2 / 4x4 の三段リフローと、ウィジェットでの文字表示。V6 は文字の大きさに式を使えず、文字まわりの命令の多くは V7 で増えたため、ADR-0012 の見直しにつながりうる

## 検討した選択肢

1. **細い一本を先に通す** — 骨組みを作り、機能を薄く端から端までつないでから、見た目を作り込む。不明点を早くつぶせる。作品としての手応えが出るのは後になる
2. **見た目を先に作り込む** — 植物の描画を先に仕上げ、手応えを早く得る。不明点の結果しだいで描き方を作り直すおそれがある
3. **骨組みと見た目を交互に進める** — 両方を小分けに進める。切り替えのコストがかかり、不明点が後ろに残りやすい

## 決定

選択肢1。次の4段階で進める。

| 段階 | 内容 |
| --- | --- |
| M1 骨組み | feature の切り出し（`:feature:showcase` / `:feature:album` / `:feature:widget`）、`:core:data`（成長データとメタデータの保存・作り直し、ADR-0011）、Koin・MVI・detekt の CI ゲート（ADR-0005） |
| M2 一本通す | Sim の本実装（経過日数・水やり・季節係数 → 枝ぶりと花の状態）、毎日の成長 tick（WorkManager）、水やりを Sim に届ける経路（ADR-0014）、三段リフローとウィジェットでの文字表示の確認（ADR-0012 を見直すかの判断） |
| M3 見た目 | チングルマの描画の作り込み、3 サイズそれぞれの構図、綿毛が回るクライマックス演出、アプリ内だけのシェーダー表現 |
| M4 仕上げ | README＋デモ GIF / 動画、技術記事、電池への配慮、アクセシビリティ |

## 理由

- 残っている不明点はどれも、描き方や画面構成に影響しうる。先につぶしておけば、M3 の作り込みが無駄にならない
- 三段リフローはセッションの 3 本柱の 1 つで、文字表示の可否は採択済みの ADR-0012 を覆しうる。見た目の作業より前の M2 で確かめる
- feature の切り出しと規約の導入（ADR-0004 / 0005）は、中身が薄いうちにやるほど安い

## 影響

- M2 が終わるまで、ウィジェットの見た目はスパイク程度のまま
- 各段階の終わりに、次の段階の計画を見直す。M2 で ADR-0012 を覆す場合は新しい ADR を起こす
